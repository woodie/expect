# expect v0.1.0

## Initial release

`expect` is a small, dependency-free matcher library for Go's standard `testing` package, built around Go 1.18+ generics -- a statically typed matcher and a plain `*testing.T` argument instead of the `interface{}`/reflection/global-fail-handler shape older assertion libraries needed before generics existed.

## Usage

```go
import . "github.com/woodie/expect"

Expect(t, resp.StatusCode).To(Equal(200))
Expect(t, resp.StatusCode).NotTo(Equal(404))
Expect(t, tags).To(DeepEqual([]string{"go", "testing"}))
Expect(t, body).To(Contain("Available Scans"))
Expect(t, err).To(Succeed())
Expect(t, elapsed).To(BeNumerically[time.Duration]("<", time.Second))
Expect(t, srv.Handler).To(BeIdenticalTo[http.Handler](mux))
Expect(t, func() { mustParse("bad") }).To(Panic())
```

## Matchers

`Equal`, `DeepEqual`, `BeIdenticalTo`, `Contain`, `Succeed`, `HaveOccurred`, `BeTrue`, `BeFalse`, `BeNumerically`, `BeAnExistingFile`, `BeADirectory`, `Panic` -- see the README's matcher table for full signatures. Every one came from an actual Ginkgo/Gomega call site ported in `gorderly` or `lambada`, not speculative parity with Gomega's full surface.

## Scope

This first release covers the matcher set above, `To`/`NotTo`/`ToNot`, and the dot-import usage pattern. Deliberately not included: async/eventually-style matchers, matcher combinators (`And`/`Or`/`Not`), and `HaveLen`/`BeEmpty` (Go's builtin `len()` already covers that case) -- see the README and `docs/COWORK.md` for the reasoning behind each. The growth policy stays real-usage-first: new matchers land when a real call site needs one, not ahead of it.
