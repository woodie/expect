# expect v0.2.0

## Breaking: `Expect(t, got)` flipped to `Expect(got, t)`

`t` moved from the first argument to the second: `Expect[T any](got T, t testing.TB) Expectation[T]`, was `Expect[T any](t testing.TB, got T) Expectation[T]`. Prompted by looking at a real call site once its surrounding `spec` blocks were already lowercase `describe`/`context`/`it`/`before`/`after` -- `Expect(t, got)` put the argument that reads like `self` first on the line, ahead of the actual subject under test. `Expect(got, t)` puts the subject first; `t` is a quiet trailing detail instead of the lead argument.

Two paths considered and ruled out first, not just this one shipped blind: `t.Expect(got)` via wrapping `testing.T` in an owned type doesn't compile for a file that asserts mixed types (`int`, `string`, `error`, `bool`) under one `t` in one suite, since Go methods can't introduce their own type parameters -- a `T`-typed wrapper can only ever fix one `T`. A generic `spec.Run[T]` (letting `spec` hand back a custom testing-context type) doesn't exist in `sclevine/spec`/`~/workspace/spec` today either. See `docs/COWORK.md` for the full reasoning.

## New: recommended lowercase `expect` alias

Since `Expect` must stay capitalized to be usable via dot-import (Go only exports capitalized identifiers across a package boundary), README now documents declaring a one-line local alias per consuming test package:

```go
func expect[T any](got T, t testing.TB) Expectation[T] { return Expect(got, t) }
```

A real generic function declaration, not a closure, so it keeps full compile-time type inference -- nothing is traded away for the lowercase spelling. Every call site then reads `expect(x, t).To(Equal(y))`, blending in with `describe`/`context`/`it`/`before`/`after` instead of standing out as the one capitalized word in the block. `expect_test.go` declares and uses this alias itself now, both to dogfood the recommended shape and confirm it compiles under dot-import.

## Upgrading

Every `Expect(t, x)` call site becomes `Expect(x, t)` -- a straightforward argument swap, no type changes. If you've adopted the lowercase alias convention, declare it once per test package and switch call sites to `expect(x, t)`. `lambada`'s five test files (see its own `docs/COWORK.md`) were updated as the real test case for this release.
