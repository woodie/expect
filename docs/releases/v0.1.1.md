# expect v0.1.1

## Fix: `spec` dependency no longer requires a local sibling checkout

`v0.1.0`'s `go.mod` pointed its `github.com/sclevine/spec` replace at a relative path (`../spec`), which only resolves on a machine with both repos checked out side by side. CI (which only checks out `expect` itself) failed outright with `replacement directory ../spec does not exist`. Repointed at the real published fork instead: `replace github.com/sclevine/spec => github.com/woodie/spec v0.1.0`. Works identically locally and in CI now, since it's a real network fetch either way.

This only affects building/testing `expect` itself (`spec` is a test-only dependency); nothing changes for code that just imports `github.com/woodie/expect` as a library.

## Upgrading

No API changes. If you have a local `replace github.com/woodie/expect => ../expect` in a consumer's `go.mod`, this release is what makes it safe to drop in favor of `require github.com/woodie/expect v0.1.1` -- confirmed against `lambada`'s full suite as the real test case.
