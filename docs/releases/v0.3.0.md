# expect v0.3.0

## New: `ContainSubstring`, `HaveLen`, `BeEmpty` matchers

The real-usage-first growth policy stands for future matchers, but these
three are the deliberate, named exception: added for naming parity with
Gomega rather than because a real `gorderly`/`lambada` call site needed
them. `ContainSubstring(substr string) Matcher[string]` is a plain alias
for `Contain`, the same shape as the existing `ToNot`/`NotTo` alias.
`BeEmpty[T any]() Matcher[T]` and `HaveLen[T any](n int) Matcher[T]` are
real additions, implemented via `reflect.ValueOf(got).Len()` so they work
across slices, arrays, maps, channels, and strings -- none of which share a
builtin length constraint. Like `BeIdenticalTo`/`BeNumerically` before
them, `HaveLen` sometimes needs an explicit type argument
(`HaveLen[[]scan](1)`), since `n` alone doesn't let Go infer `T`.

The README's matcher table and `expect.go`'s own function order were also
reordered to follow Gomega's own documented category order, rather than
the order each matcher happened to be added in, so the two lists line up
side by side for anyone comparing them.

## Also

A `Makefile` (`build`/`lint`/`test`/`check`) was added, matching
`gorderly`/`gomeleon`/`humane`'s own shape -- see the README's
"Development" section.

## Upgrading

No breaking changes -- every `v0.2.0` call site keeps working as-is.
`ContainSubstring`, `HaveLen`, and `BeEmpty` are new, opt-in matchers only.
